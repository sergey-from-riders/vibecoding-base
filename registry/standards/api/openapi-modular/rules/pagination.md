# Пагинация

## Коротко

Для потенциально большой коллекции ограничьте размер страницы и задайте полный порядок. Cursor продолжает выбранную выборку, но не доказывает права доступа.

## Плохо

```text
GET /users → вся таблица.
ORDER BY created_at без уникального дополнения: страницы нестабильны.
```

## Хорошо

```text
Профиль примера: limit по умолчанию 50, максимум 200.
Порядок: created_at DESC, user_id DESC.
Cursor связывает последнюю пару значений, фильтры и tenant.
Ответ: items и next_cursor; в конце next_cursor = null.
```

## Почему

Размеры 50/200 и имя next_cursor — решения примера. Контракт определяет целочисленный диапазон limit и реакцию на превышение: явная ошибка либо документированное ограничение; отсутствие использует default, null/строка/отрицательное не принимаются как «без лимита». Уникальный tie-breaker необходим даже при cursor. PostgreSQL не гарантирует порядок без ORDER BY.

## Когда применять

Для HTTP-списков. Cursor делайте непрозрачным и проверяемым сервером; свяжите с фильтрами, сортировкой и областью данных, но проверяйте текущие права на каждой странице. Неверный/истекший cursor возвращает документированную ошибку, а не чужую выборку.

Keyset по неизменяемой паре уменьшает сдвиги от вставок, но не создает snapshot: изменения ключа сортировки могут дать пропуски/повторы. Если нужен точный экспорт состояния, используйте согласованный snapshot или отдельную задачу экспорта. Offset допустим для небольших стабильных списков с учетом стоимости больших смещений.

## Как проверить

1. Несколько строк с одинаковым created_at → последовательный обход без изменения данных → каждая строка ровно один раз → список ID и полный ORDER BY.

2. limit = -1, 0, строка или выше максимума → запрос → согласованная ошибка/ограничение, память не растет без границ → ответы и число строк.

3. Cursor пользователя A применен в другом tenant или с иными фильтрами → отказ без данных A; конкурентная вставка → поведение соответствует documented snapshot/live модели → тест двух клиентов.

## Человек

Определяет смысл обхода при изменениях, максимальный размер и необходимость точного snapshot.

## Агент

Проверяет границы limit, полный порядок, связь cursor с выборкой и повторную авторизацию; не обещает snapshot без его реализации.
