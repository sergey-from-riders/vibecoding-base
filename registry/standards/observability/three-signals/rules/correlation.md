# Correlation ID

## Коротко

Связывай относящиеся к операции журналы и вызовы через согласованный контекст, различая request ID приложения, trace ID и span ID.

## Плохо

```text
Входной X-Request-ID без проверки записывается в лог.
trace_id используется как tenant; наличие ID обещает полную трассу навсегда.
```

## Хорошо

```text
HTTP request: безопасный request ID и валидированный trace context.
Логи: идентификаторы текущей операции; права проверяются отдельно.
Фоновое задание: причинный контекст/ссылка и собственный job ID.
Если trace не сохранен: диагностика по доступным логам/метрикам,
без обещания отсутствующих spans.
```

## Почему

Корреляция упрощает расследование, но не заменяет авторизацию и не гарантирует, что все связанные события были записаны.

## Когда применять

Для операций через несколько компонентов или асинхронные этапы. Одному простому процессу может хватить request ID. Формат W3C относится к traceparent/tracestate; произвольный прикладной ID не нужно объявлять trace ID.

### Подробные условия

Имена request ID и способ его возврата клиенту — контракт проекта; W3C Trace Context определяет другие, конкретные поля и правила обработки.

Входной ID проверяется по формату и длине. При отсутствии/недопустимом значении приложение создает безопасный ID либо отклоняет запрос по явному контракту; не отражай управляющие символы в журнал. Для traceparent используй совместимый propagator, а не собственную обрезку строки. Внешний контекст и baggage не являются доказательством личности/прав; не включай секреты и чувствительные данные. Для фоновой задачи сохрани причинную связь через поддерживаемый контекст или span link, даже если HTTP-запрос закончился. Sampling, потеря экспорта и retention ограничивают доступность полной трассы.

## Как проверить

- Один запрос прошел сервисы → найти события → согласованы trace/request ID и область операции.
- ID слишком длинный или содержит перевод строки → отправить → безопасная замена/отказ, внедрения строки в журнал нет.
- Фоновая задача после ответа, trace не sampled → расследовать → причинная связь сохранена где предусмотрено, отсутствующая трасса обозначена честно.

## Человек

Выбирает срок хранения, политику доверия и минимальный набор корреляции.

## Агент

Проверяет propagator и безопасные ID; не использует контекст трассировки для доступа и не обещает полноту без учета sampling.
