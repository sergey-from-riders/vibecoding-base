# SLO и error budget

## Коротко

SLO задает целевое значение конкретного SLI для пользовательского сценария.

## Плохо

```text
CPU < 80% объявлен пользовательской доступностью.
Окно без трафика = 100%; два разных процента просто усредняются.
```

## Хорошо

```text
Сценарий: допустимые запросы завершения заказа за скользящие 28 дней.
Good: завершение без внутренней ошибки в выбранный предел времени.
Target 99,9% — пример решения продукта, не универсальная норма.
При 100 000 eligible бюджет = 100 плохих событий.
Нет измерений: unknown; превышение бюджета запускает согласованное действие.
```

## Почему

Точная формула показывает, чье качество измеряется и какое решение следует из отклонения. Инфраструктурный показатель может помогать диагностике, но не подменяет пользовательский результат.

## Когда применять

Для сервиса, которому нужен управляемый уровень надежности. Окно, цель и допустимые исключения определяются потребностью продукта; HTTP 4xx не исключаются автоматически без учета сценария. Для малого трафика отдельно выбирается метод оценки неопределенности. SLO не является SLA без соответствующего обязательства.

### Подробные условия

Определи good/eligible события, источник измерения, единицы, окно и исключения до просмотра результата. Для доли успеха SLI = good / eligible; отсутствие eligible или потеря измерений означает no-data/unknown по опубликованной политике, а не автоматически 100%.

Согласуй сегменты пользователей и агрегацию: общая доля считается из суммы числителей и знаменателей, не среднего процентов разных групп. Перцентили также не усредняются. Для запросного SLO допустимый error budget в окне = (1 − target) × eligible; сравни фактические плохие события с бюджетом. Порог расхода/скорости расхода, действие, владелец и условие возобновления выпуска выбираются проектом.

## Как проверить

- Контрольный набор 100 000 eligible, 99 930 good, target 0,999 → вычислить → SLI 99,93%, 70 плохих, остаток бюджета 30.
- Ноль запросов либо пропал источник → оценить окно → no-data/unknown, без ложного 100%.
- Бюджет/порог расхода нарушен → применить политику → выполнено назначенное действие, известны владелец и условие завершения.

## Человек

Выбирает цель и последствия расхода бюджета исходя из потребностей пользователей.

## Агент

Проверяет формулу, источник, окно и агрегацию на контрольных данных; не выводит SLO из показателя CPU.
