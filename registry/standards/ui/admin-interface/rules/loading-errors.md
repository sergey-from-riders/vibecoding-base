# Загрузка и ошибки

## Коротко

Интерфейс различает загрузку, пустой результат, отказ, конфликт и неизвестный исход изменения.

## Плохо

```text
Любая ошибка отображается как «Нет записей». После timeout удаления кнопка предлагает повторить без проверки результата.
```

## Хорошо

```text
Read: loading / ready / empty / stale / unauthorized / forbidden / failed.
Write: pending / succeeded / rejected / conflict / unknown.
При stale сохранены прежние данные и время обновления; при unknown проверяется operation_id.
```

## Почему

Разные состояния требуют разных действий пользователя. Ошибка обновления не доказывает отсутствие данных или отсутствие эффекта мутации.

## Когда применять

Для асинхронных чтений и изменений. Подписи и набор состояний могут различаться, но смысл должен оставаться различимым.

### Требования

- Empty подтверждается успешным ответом с пустым набором. 401/истечение сессии, 403, сетевой отказ и конфликт версии показываются отдельно без утечки закрытых данных.
- При отказе обновления сохраненные данные отмечаются как устаревшие с временем/статусом; опасные действия над ними учитывают ревизию.
- Неизвестный исход мутации разрешается проверкой состояния или идемпотентным повтором. Отмена старого чтения не превращается в ошибку нового запроса.
- Объявляйте значимые изменения доступным status/alert по срочности; не перемещайте фокус на каждую подгрузку. После ошибки фокус остается у контекста действия либо переходит к сводке, когда это нужно для исправления.

## Как проверить

- Проверьте empty, offline, 401, 403, conflict, timeout после эффекта и поздний ответ отмененного запроса.
- Проверьте объявление скринридером, положение фокуса и отсутствие ложного успешного или пустого состояния.

## Человек

Определяет понятный следующий шаг для каждого состояния.

## Агент

Моделирует состояния явно и проверяет задержки и повторы.
