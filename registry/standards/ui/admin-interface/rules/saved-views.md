# Сохраненные представления

## Коротко

Сохраненный вид, параметры URL и временная позиция навигации имеют разные области хранения и определенный приоритет.

## Плохо

```text
Личный вид молча перезаписывает query из URL; персональные данные фильтра попадают в публичную ссылку.
```

## Хорошо

```text
Приоритет: явный URL > выбранный сохраненный вид > командный default.
Вид: field_id, sort, filters, schema_version.
Позиция/фокус: история текущей вкладки; чувствительный фильтр: закрытый server-side state.
```

## Почему

Разделение предотвращает неожиданные изменения открытой ссылки и утечку параметров через историю, журналы и Referer.

## Когда применять

Для настраиваемых списков. Полный набор сохраняемых параметров и область общего доступа определяются продуктом.

### Требования

- Сохраненный вид содержит долговременную конфигурацию; URL содержит допустимые воспроизводимые параметры запроса; scroll/focus и незавершенный выбор принадлежат временной сессии навигации.
- Применяйте явный приоритет URL, выбранного вида и командного default. Отсутствующий параметр и явно пустой параметр различаются.
- Версионируйте схему вида, мигрируйте известные поля, удаляйте неизвестные и повторно проверяйте права. Общий вид не выдает права на данные.
- Не помещайте секреты и чувствительные значения в URL. Для закрытого состояния используйте ограниченный серверный идентификатор с проверкой доступа и сроком жизни.

## Как проверить

- Откройте ссылку при другом личном default, измените схему и права: результат соответствует приоритету и доступу.
- Проверьте URL, историю, журналы и восстановление позиции без переноса приватного состояния между пользователями.

## Человек

Определяет полезные командные виды.

## Агент

Сохраняет запрос в URL, настройки по пользователю, позицию по стабильному ID.
