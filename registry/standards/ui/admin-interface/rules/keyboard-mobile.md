# Клавиатура и мобильный экран

## Коротко

Для принятого профиля WCAG 2.2 AA проверяйте критические сценарии клавиатурой, скринридером и при изменении масштаба.

## Плохо

```text
Два скриншота desktop/mobile объявлены доказательством доступности. Drag обязателен, фокус скрыт, диалог не возвращает его.
```

## Хорошо

```text
Матрица: клавиатура; скринридер; 320 CSS px; zoom; контраст; target size.
Сценарии: поиск, таблица, форма, ошибка, диалог, публикация.
Для каждого критерия указано pass/fail/not-applicable и свидетельство.
```

## Почему

Доступность относится к поведению и полным сценариям. Автоматические проверки обнаруживают часть дефектов, но не подтверждают полное соответствие.

## Когда применять

Для web-интерфейсов, где проект выбрал WCAG 2.2 AA. Юридический уровень соответствия определяется отдельно от этого профиля.

### Требования

- Управление доступно клавиатурой без ловушек; порядок фокуса соответствует задаче, индикатор видим и не перекрыт фиксированными элементами.
- Проверяйте reflow при ширине 320 CSS px с применимыми исключениями для двумерного содержания; масштаб и длинный текст не скрывают действия.
- Проверьте контраст текста и компонентов по соответствующим критериям WCAG, target size 2.5.8 с его исключениями, а также доступную альтернативу drag.
- Проверьте имя/роль/состояние, уведомления, ошибки, диалоги с возвратом фокуса и виртуализированные списки на выбранной документированной связке браузера и скринридера.
- Зафиксируйте область аудита, версии средств, автоматические и ручные проверки. Несколько успешных страниц не подтверждают весь сайт.

## Как проверить

- Выполните критические сценарии без мыши и со скринридером; запишите конкретные дефекты и проверенные критерии.
- Проверьте масштаб, ширину, контраст, размеры целей, диалоги и восстановление фокуса после исчезновения элемента.

## Человек

Определяет критические сценарии для приёмки.

## Агент

Проверяет фокус, семантику и альтернативные способы действия.
