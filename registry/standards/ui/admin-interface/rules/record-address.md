# Адрес записи

## Коротко

Адрес записи уникален в заданной области, нормализуется по явной политике и безопасно изменяется.

## Плохо

```text
Два редактора получают один slug; старые адреса образуют цепь redirects, а target берется из произвольного URL пользователя.
```

## Хорошо

```text
Ключ уникальности: site_id + locale + normalized_path.
Смена slug атомарно резервирует новый путь и обновляет aliases на конечный canonical.
Redirect разрешен только для публичной цели в допустимом origin/path.
```

## Почему

Адрес является частью внешнего контракта. Проверка доступности перед сохранением не заменяет атомарную уникальность.

## Когда применять

Для объектов с публичным или внутренним человекочитаемым URL. Политика может сохранять непрозрачный ID как неизменяемый адрес.

### Требования

- Определите домен/site, локаль, регистр, Unicode-нормализацию, percent-encoding, slash и query. Значимые параметры не удаляются произвольно.
- Резервируйте нормализованный адрес атомарно с проверкой base revision и уникальности. Конфликт предлагает другой адрес без потери ввода.
- Старые aliases ведут непосредственно на конечный canonical без циклов. Повторное использование старого пути допускается только по документированной миграционной политике.
- Redirect-target проверяется по allowlist; внешние произвольные URL запрещены для локального переименования. Приватная запись не раскрывается публичным redirect. Для удаления задайте 404/410 либо обоснованную релевантную замену.

## Как проверить

- Одновременно сохраните одинаковые и эквивалентные Unicode/case варианты; должен остаться один владелец адреса.
- Проверьте повторное переименование, alias-цикл, внешний target, query/locale и переход к приватной или удаленной записи.

## Человек

Определяет адрес и решение об удалении старых ссылок.

## Агент

Проверяет уникальность и историю, сохраняет прямой переход к текущему адресу.
