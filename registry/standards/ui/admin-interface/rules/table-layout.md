# Табличные представления

## Коротко

Выбирайте таблицу для сравнения однотипных записей и групповых операций по явным задачам пользователя.

## Плохо

```text
Каталог из 500 услуг: цена и статус доступны только после открытия каждой карточки. На телефоне исчезают название и действие открытия.
```

## Хорошо

```text
Задачи: сравнить цену трех услуг; найти неопубликованные; выделить 20 записей.
Столбцы: Услуга | Цена, валюта | Статус | Действия.
При 320 CSS px доступны название, статус и основные действия; остальные данные раскрываются явно.
```

## Почему

Представление оценивают по выполнению задач, а не по внешнему виду. Семантика таблицы помогает связать значение с заголовком. Конкретный набор столбцов является соглашением продукта.

## Когда применять

Для каталогов, заказов и других сравнимых объектов. Календарь, список или карточки допустимы, если проверка типовых задач подтверждает их пригодность.

### Требования

- До выбора представления зафиксируйте 3–5 основных задач, типичный и предельный объем, длинные значения и пустые данные. Сравните прототипы на этих данных.
- Для статической таблицы используйте table, caption или доступное имя, th и связи заголовков с ячейками. Роль grid допускается только с реализованной моделью управления фокусом.
- Полное значение должно быть доступно без наведения мыши. Перенос, раскрытие или горизонтальная прокрутка не должны терять данные.
- На узком экране сохраняйте идентификатор записи, значимые для задачи состояния и доступ к основным действиям. Скрытие вторичных столбцов должно иметь доступный способ их просмотра.

## Как проверить

- Выполните зафиксированные задачи на типичном и предельном наборе; запишите результат и число переходов.
- Проверьте заголовки скринридером, длинные значения, 200% масштаб и ширину 320 CSS px; двумерная таблица может иметь собственную прокрутку.

## Человек

Выбирает свойства для сравнения и основную задачу списка.

## Агент

Показывает типовые строки, проверяет узкий экран и клавиатуру.
