# Постепенная загрузка

## Коротко

Постепенная загрузка сохраняет порядок, состояние запроса и доступный способ продолжения.

## Плохо

```text
Ответ старого поиска дописывается к новому. Total=100 показан как точный, хотя это оценка индекса.
```

## Хорошо

```text
query_version=9; page_size=50; cursor связан со снимком и сроком.
Ответ query_version=8 отброшен.
Статус: «Загружено 50; всего примерно 120». Конец: next_cursor=null.
```

## Почему

Подгрузка и виртуализация решают разные задачи. Они не должны разрушать фокус, адресуемость и согласованность набора.

## Когда применять

Для больших списков. Обычная постраничная навигация допустима; бесконечная прокрутка не обязательна.

### Требования

- Контракт задает максимальный page_size, непрозрачный cursor, версию нормализованного запроса, срок жизни и однозначный признак конца. Просроченный cursor запускает явное обновление.
- Поздние ответы предыдущего запроса не добавляются к текущему. Повтор страницы не создает дубликаты по ID.
- Для total различайте exact, approximate и unavailable; не вычисляйте точность из наличия числа.
- Предоставьте доступную кнопку продолжения или эквивалентную навигацию. Виртуализация сохраняет активный элемент, контекст строк и восстановление позиции; grid требует полной клавиатурной модели.

## Как проверить

- Задержите старый ответ, смените запрос, повторите страницу и доведите до конца: нет смешения, дублей и бесконечного запроса.
- Проверьте клавиатуру/скринридер, возврат из карточки, удаление активной строки и истечение снимка.

## Человек

Определяет размер порции и необходимость точного общего количества.

## Агент

Не смешивает ответы разных запросов и восстанавливает позицию списка.
