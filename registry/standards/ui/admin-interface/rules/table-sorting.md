# Сортировка таблиц

## Коротко

Сортируйте весь набор по типизированному полному порядку; привязывайте пагинацию к запросу и модели согласованности.

## Плохо

```text
Страница 1 сортируется в браузере как строки: 100, 20, 3.
Следующая страница использует курсор от другого фильтра.
```

## Хорошо

```text
Запрос: tenant=7, currency=RUB, sort=(price ASC NULLS LAST, id ASC).
Курсор связан с query_hash, sort_version и snapshot_id.
Смена фильтра сбрасывает курсор; просроченный снимок требует нового просмотра.
```

## Почему

Дополнительный уникальный ключ устраняет неопределенность равных значений, но сам по себе не фиксирует меняющийся набор. Модель снимка или явно живая выдача должна быть согласована с задачей.

## Когда применять

Для серверной таблицы. Локальная сортировка допустима, если полный ограниченный набор уже загружен и это подтверждено контрактом.

### Требования

- Задайте типы, порядок null, collation и регистр строк, часовой пояс дат. Не сравнивайте строки с числами неявно. Смешанные валюты сортируйте отдельно либо по документированной нормализации.
- Добавьте стабильный уникальный tie-breaker; сервер применяет тот же порядок ко всем страницам.
- Курсор связывается с нормализованными фильтрами, правами/tenant, направлением, версией сортировки и выбранным снимком. Несовместимый или истекший курсор отклоняется.
- Для изменяемых данных выберите snapshot/PIT либо документируйте возможные изменения живой выдачи и способ обновления. Показывайте направление сортировки доступным способом.

## Как проверить

- Проверьте равные значения, null, кириллицу/латиницу, числа и валюты на нескольких страницах.
- Измените данные между страницами и смените фильтр: снимок остается согласованным либо интерфейс явно начинает новую выдачу; устаревший курсор не применяется.

## Человек

Определяет смысл сравнения, валюту и обработку пустых значений.

## Агент

Реализует типизированную серверную сортировку и проверяет границы страниц.
