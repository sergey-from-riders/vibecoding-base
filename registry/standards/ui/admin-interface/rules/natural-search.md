# Поиск на естественном языке

## Коротко

Поиск на естественном языке преобразует запрос в проверяемые типизированные условия и сохраняет точные фильтры.

## Плохо

```text
«Не дороже 1000 евро до пятницы» незаметно превращается в price<1000 RUB; нераспознанная часть отброшена.
```

## Хорошо

```text
Условия: price <= 1000; currency=EUR; date <= выбранная дата, timezone=Europe/Moscow.
Неоднозначное «до пятницы» требует выбора даты.
Распознанные условия видны и редактируются; точные фильтры доступны.
```

## Почему

Естественный язык является дополнительным вводом. Он не заменяет точные повторяемые запросы без проверки пригодности для конкретной задачи.

## Когда применять

Для поиска, где свободный ввод подтвержден пользовательскими сценариями. В отчетности, бухгалтерских и регуляторных операциях точные фильтры обычно остаются основным контрактом.

### Требования

- Используйте типизированное промежуточное представление: поле из allowlist, оператор, значение, единица/валюта, timezone и версия схемы. Не исполняйте сгенерированный SQL или произвольное выражение.
- Показывайте распознанные условия и остаток текста; неоднозначные значения требуют уточнения либо явного безопасного предложения, а не скрытого предположения.
- Отрицания, включительность границ и относительные даты определяются явно. Ограничения tenant и доступа применяет сервер независимо от интерпретатора.
- До включения оцените фиксированный набор запросов: отрицания, интервалы, единицы, даты, опечатки, неизвестные поля и нераспознанный остаток. Задайте приемлемую точность по задачам.

## Как проверить

- Сверьте интерпретацию с эталонными условиями и точными фильтрами; зафиксируйте ошибочные/неоднозначные случаи.
- Проверьте смену локали, валюту, timezone и попытку обойти ограничения доступа через текст запроса.

## Человек

Задаёт словарь полей, единицы и смысл запросов.

## Агент

Преобразует запрос в проверенные условия; не исполняет произвольный SQL/DSL от модели.
