# Автосохранение черновика

## Коротко

Автосохранение сохраняет определенную ревизию черновика и защищает ввод от потерянных обновлений.

## Плохо

```text
Ответ сохранения A приходит после B и помечает весь ввод сохраненным. Другая вкладка молча перезаписывает новую версию.
```

## Хорошо

```text
local_seq=12; base_revision=41; request_key=save_12.
ack(seq=11) не подтверждает seq=12.
Состояния: pending → in-flight → saved / failed / conflict / unknown.
При conflict локальный ввод сохранен для сравнения.
```

## Почему

Индикатор «сохранено» относится к конкретной подтвержденной версии. Задержка и надежность автосохранения задаются измеримым контрактом проекта.

## Когда применять

Для редакторов черновиков. Для чувствительных данных локальная долговременная копия разрешается только явной политикой хранения.

### Требования

- Фиксируйте local edit sequence и базовую серверную ревизию. Сервер атомарно проверяет ревизию; ответы могут приходить в любом порядке и подтверждают только свой sequence.
- Задайте debounce и максимальную задержку отправки при непрерывном вводе. Показывайте pending, in-flight, failed, conflict и unknown; saved означает подтверждение всех актуальных изменений.
- При неизвестном исходе выясните результат по request_key или повторите идемпотентно. Не выполняйте слепой overwrite после конфликта между вкладками/устройствами.
- Сохраните несохраненный ввод до разрешения конфликта. Определите восстановление сессии, шифрование/запрет локального хранения, срок и очистку при logout/смене пользователя; серверная история не заменяется локальным кешем.

## Как проверить

- Отправьте A/B и переставьте ответы; latest sequence не должен быть ошибочно подтвержден ранним ack.
- Проверьте две вкладки, timeout после записи, offline/reload, logout и смену аккаунта; нет потери ввода или доступа к чужой копии.

## Человек

Определяет жизненный цикл и срок хранения черновиков.

## Агент

Сериализует сохранения, показывает ошибки и защищает ввод при уходе.
