# Состояния интерфейса

## Коротко

Для асинхронного сценария определи состояния, доступные действия и судьбу данных/ввода.

## Плохо

```text
Любая ошибка → [] и «ничего не найдено».
Повтор удаляет заполненную форму; успех показывается только зеленым цветом.
```

## Хорошо

```text
Initial loading: индикатор и доступная отмена, если она поддерживается.
Refreshing: предыдущий допустимый результат + статус обновления.
Empty: объяснение отсутствия результата и возможное действие.
Forbidden: сообщение о доступе, приватные данные скрыты.
Offline/error: ввод сохранен; безопасный повтор по контракту операции.
Optimistic failure: локальный эффект отменен/помечен, ввод не потерян.
```

## Почему

Явные состояния не позволяют сообщить ложный успех, скрыть отказ доступа или уничтожить работу пользователя при восстановлении.

## Когда применять

Для списков, форм и фоновых запросов. Набор состояний выбирается по реальным переходам: приложение без offline-режима не обязано его реализовывать, но сетевой отказ должен иметь понятный результат. Optimistic UI — опция со своим rollback, не обязательный паттерн.

### Подробные условия

Не своди отсутствие данных, отсутствие прав и сетевой отказ к пустому списку. При повторе сохраняй локальный ввод и последний допустимый результат, если доступ к нему еще действителен. После потери прав/смены пользователя прежние приватные данные не показываются.

Сообщение о ходе/результате должно быть доступно без чтения цвета: используй текст, программно определимый status/live region там, где сообщение подходит под WCAG 4.1.3, и не перемещай фокус без необходимости. Срочное alert применяется по смыслу, а не ко всякому обновлению.

## Как проверить

- Первая загрузка, затем refresh → задержать ответ → видны разные статусы, допустимые данные сохраняются; status читается вспомогательной технологией.
- Сервер вернул forbidden → отобразить → нет ложного empty и раскрытия прежнего приватного содержимого.
- Пользователь ввел текст, сохранение не прошло → повторить → ввод сохранен, повтор не дублирует необратимый эффект.

## Человек

Выбирает тексты, действия и моменты изменения фокуса по сценарию.

## Агент

Проверяет переходы, доступность сообщений и сохранность ввода при ошибке/повторе.
