# Web performance

## Коротко

Определи важные пользовательские сценарии и измеряй изменение в воспроизводимых условиях: страница/действие, версия сборки, устройство, браузер, сеть и состояние кеша.

## Плохо

```text
«Быстро на моем ноутбуке; Lighthouse однажды показал 100».
После изменения не зафиксированы сборка, сеть, кеш и выборка.
```

## Хорошо

```text
Сценарий: открыть каталог и изменить фильтр.
Сравнение: baseline B и кандидат C, одно устройство/сеть/cache profile.
Lab: несколько повторов и разброс; field: p75 по заданному окну и сегменту.
Бюджет и допустимая регрессия определены заранее.
Нет field-выборки → лабораторный результат, без заявления о field SLO.
```

## Почему

Одинаковые условия отделяют влияние изменения от сети и кеша; распределение задержки отражает больше пользователей, чем единичное среднее.

## Когда применять

Для интерактивного веб-продукта, где задержка влияет на сценарий. Оптимизируй измеренный bottleneck; мемоизация, динамические импорты и server rendering не обязательны без причины. Проверенная страница Web Vitals описывает LCP/INP/CLS; инструменты и пороги сверяй при обновлении.

### Подробные условия

Разделяй полевые данные пользователей и лабораторный прогон; один Lighthouse score не подтверждает распределение реальных задержек.

Для веб-интерфейса уместны LCP, INP и CLS. Рекомендации Core Web Vitals для хорошего опыта: LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1 на p75, отдельно для mobile/desktop. Это внешние ориентиры, а не автоматически принятый SLO продукта. Проект задает бюджет для своих сценариев, допустимую регрессию, размер выборки и условие сравнения; при малом трафике обозначает неопределенность. Бюджет JS или число запросов нужен, если связан с наблюдаемой проблемой.

## Как проверить

- B и C в одинаковом профиле → измерить → известны метрики, разброс и соответствие выбранному бюджету.
- Улучшен lab score, но ухудшен field INP → оценить → результаты не смешаны, регрессия видима.
- Трафик мал или замер только на desktop → сформировать отчет → не заявлена надежная mobile/p75-оценка без данных.

## Человек

Выбирает важные сценарии и приемлемый бюджет по потребностям пользователей.
