# Зависимости проекта

## Коротко

Добавляй зависимость для конкретного требования, которое существующее решение не выполняет приемлемым способом.

## Плохо

```text
Добавить Redis, очередь и новую ORM «на будущее».
Версии: latest. Кто обновляет и зачем это нужно — неизвестно.
```

## Хорошо

```text
Требование: завершить фоновую обработку в согласованное время.
Измерение: существующий механизм не выдерживает выбранный профиль нагрузки.
Выбор: сравнить его доработку и отдельный компонент по этому профилю.
Запись решения: версия, лицензия, поддержка, security review, владелец.
Пересмотр: требование снято либо стоимость поддержки выше пользы.
```

## Почему

Зависимость добавляет не только функцию, но и обновления, отказ, лицензионные и эксплуатационные обязанности. Выбор должен иметь проверяемую причину.

## Когда применять

Для новых библиотек, сервисов и существенных обновлений. NIST SSDF 1.1 PW.4 дает рекомендации по компонентам; OSPS v2026.08.28 описывает отдельные контроли по уровням. Ссылка на них не означает сертификацию или обязанность внедрить весь framework. Локальная норма — записать достаточное для своего риска решение.

### Подробные условия

Сравни как минимум сохранение текущего решения и выбранную альтернативу: функцию, совместимость, поддержку/окончание поддержки, лицензию, известные уязвимости, обновление и стоимость эксплуатации/замены. Отсутствие известных CVE не доказывает безопасность.

Зафиксируй версию или воспроизводимый способ разрешения, владельца обновления и условие удаления зависимости. Для исполняемых пакетов проверь происхождение и влияние установки/обновления на сборку. Сложность оценки соразмерна доверию и риску: небольшой пакет форматирования и внешний платежный сервис требуют разных проверок.

## Как проверить

- Есть измеримое ограничение → сравнить варианты на одном профиле → выбранный вариант удовлетворяет порогу, результат сохранен.
- Пакет не поддерживается или нарушает обязательные ограничения → оценить → отклонен либо явно согласовано исключение с мерой и сроком.
- Требование исчезло → пересмотреть использование → зависимость удалена после проверки потребителей либо сохранена с новой причиной.

## Человек

Определяет порог принятия и владельца поддержки.

## Агент

Проверяет текущие первоисточники версии, лицензии и поддержки; не подменяет отсутствие данных положительной оценкой.
