# Контракты компонентов

## Коротко

До независимой реализации сторон определи наблюдаемый контракт границы: операции, входы и выходы, обязательность, типы, единицы, ограничения, отсутствие/null, ошибки и права.

## Плохо

```text
Клиент считает amount дробным числом рублей.
Сервер возвращает целое число копеек; null и отсутствие трактуются случайно.
```

## Хорошо

```text
Контракт примера: totalMinor — обязательное целое число в копейках.
discountMinor — необязательно; отсутствие означает 0; null запрещен.
Потребитель: отображение суммы; окончательный расчет выполняет сервер.
SPEC-4 → AC-4.1: корректная сумма; AC-4.2: чужой счет недоступен.
Изменение типа: проверить старого клиента; при несовместимости — миграция.
```

## Почему

Точный контракт предотвращает разные трактовки одного JSON и делает приемку независимой от структуры реализации.

## Когда применять

Для API, событий, библиотечных интерфейсов и других границ независимого изменения. Для локальной функции достаточно типа и теста ее контракта. OpenAPI применим к HTTP API; используй версию, поддержанную реальными инструментами, а не автоматически последнюю спецификацию.

### Подробные условия

Каждое поле имеет потребителя и назначение; расширения добавляются по потребности, а не ради одинакового вида объектов.

Свяжи требование с приемкой и реализацией, например SPEC-4 → AC-4.1 → проверка API. Для изменения перечисли затронутых потребителей и проверь совместимость их версий с поставщиком. Даже добавление поля может ломать строгий декодер. Формат ошибок, HTTP и доступ описываются связанными API/security-правилами; не создавай параллельную конкурирующую норму.

## Как проверить

- Валидный вход → вызвать обе реализации → согласованы значение, единицы и права; AC связан с результатом.
- Отсутствующее необязательное поле и явный null → передать отдельно → соблюдены разные условия контракта.
- Поменялся тип/обязательность → прогнать старого потребителя с новым поставщиком → несовместимость выявлена до выпуска.

## Человек

Определяет бизнес-семантику поля и принимает несовместимое изменение.

## Агент

Проверяет потребителей, обновляет один контракт и трассировку приемки; не добавляет поле без назначения.
