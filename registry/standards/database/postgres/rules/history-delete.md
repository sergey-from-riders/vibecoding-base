# История и удаление данных

## Коротко

Выбирайте soft delete, версии содержимого и аудит отдельно. Флаг deleted_at не обеспечивает историю, контроль доступа или окончательное удаление.

## Плохо

```sql
Есть deleted_at, но поиск и export читают все строки.
Восстановление молча занимает email новой активной записи.
```

## Хорошо

```sql
-- Фрагмент PostgreSQL 18: email_key и tenant_id NOT NULL.
CREATE UNIQUE INDEX users_active_email_unique
  ON users (tenant_id, email_key)
  WHERE deleted_at IS NULL;
-- Обычное чтение включает deleted_at IS NULL.
-- Восстановление — UPDATE с обработкой конфликта уникальности.
```

## Почему

Частичный индекс защищает выбранную уникальность только активных строк; он не создает фильтр доступа. После повторной регистрации восстановление старой записи может законно конфликтовать. Политика должна сохранить новую запись и вернуть конфликт либо выполнить отдельно согласованное объединение.

## Когда применять

Если продукт требует восстановления, истории или аудита. При soft delete перечислите чтения, связи, поиск, export, кеш и фоновые задачи, которые должны исключать удаленное. Восстановление проходит текущую авторизацию и ограничения.

Для аудита определите событие, актера, время, объект, минимальные изменения и ограничение записи/чтения. Обычный триггер может фиксировать изменение, но не делает аудит неизменяемым для владельца БД и не устанавливает личность конечного пользователя автоматически. Для версии содержимого задайте срок и способ восстановления отдельно.

Purge охватывает БД и связанные файлы/индексы/кеш по выбранной политике. Резервные копии имеют свой срок: после restore должна повторно применяться подтвержденная информация об удалениях. Сроки и исключения задает проект; это правило не обещает мгновенное физическое стирание всех копий.

## Как проверить

1. Активная запись удалена → обычные read/search/export → данные не выдаются; разрешенный restore → возвращает ту же запись → результаты чтения и аудит.

2. Email удаленного пользователя уже занят → restore → явный конфликт без перезаписи новой записи → 23505/контрактный ответ и две сохраненные истории.

3. Наступил срок purge → очистка и затем учебный restore → связанные копии обработаны по политике, удаленные записи не возвращены пользователю → отчет очистки и восстановления.

## Человек

Определяет восстановление, сроки, исключения хранения и требования к доказуемости аудита.

## Агент

Проверяет все чтения и конфликт restore; описывает фактические границы purge и права на аудит.
