# Дата и время: timestamptz

## Коротко

Различайте момент времени, календарную дату и локальное расписание. timestamptz хранит момент, но не исходное название зоны.

## Плохо

```sql
CREATE TABLE meeting (starts_at text);
-- '09.11.2026 10:00': формат и зона неизвестны.
```

## Хорошо

```sql
CREATE TABLE meeting (starts_at timestamptz NOT NULL);
INSERT INTO meeting VALUES ('2026-11-09T10:00:00+03:00');
-- Для одного момента исходная зона не нужна, если ее никто не использует.
```

## Почему

В PostgreSQL 18 вход timestamptz со смещением переводится в UTC, вывод зависит от TimeZone сессии. Если смещения нет, используется TimeZone сессии: это опасная неявность внешнего контракта. Само значение не хранит Europe/Moscow. Добавляйте отдельную зону только для ее дальнейшего использования, например пересчета локального расписания.

## Когда применять

Для событий/аудита используйте timestamptz; для даты рождения — date без выдуманного часового пояса. Для будущего повторяющегося локального события храните местные дату/время, IANA zone и правило повтора; это другой контракт, чем один UTC-момент.

Принимайте момент через согласованный формат с Z/offset. Если пользователь задает местное время в зоне, проверьте ее наличие в поддерживаемой базе и определите DST gap/fold: несуществующее время отвергнуть/сдвинуть по политике, двузначное — выбрать явно установленное смещение/вариант. Нельзя полагаться на неявный выбор парсера. Для будущих повторов изменения tzdata могут менять получившиеся моменты; задайте правило пересчета. Исторический ID time-money сохраняется для ссылок, деньги находятся в database.money.

## Как проверить

1. Один момент с +03:00 → чтение в UTC и другой зоне → тот же instant → сравнение epoch, а не строк отображения.

2. Внешний instant без offset или неизвестная IANA zone → ввод → документированный отказ, без подстановки зоны сервера → ответ валидатора.

3. Локальное время попало в DST gap/fold → построение расписания → согласованный отказ/выбор, не случайность парсера → fixtures переходов выбранной tzdata.

## Человек

Выбирает семантику поля и продуктовую политику неоднозначного местного времени.

## Агент

Проверяет тип, входной offset, валидность зоны и DST-сценарии; не добавляет zone к date или instant без потребности.
