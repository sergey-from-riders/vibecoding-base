# Рабочее дерево Git

## Коротко

До правки установи состояние index, рабочей копии и untracked-файлов; учитывай ignored-данные при операции, которая способна их удалить.

## Плохо

```text
git switch -c task
# Ветка якобы защитила локальные файлы.
git reset --hard
git clean -fdx
```

## Хорошо

```text
До работы: status и diff index/working tree; известны untracked.
Для независимой задачи: отдельный worktree от нужного commit.
Для общей правки: свежий контекст, минимальный patch своего участка.
После: сравнить итоговый diff; чужой staged/unstaged текст сохранен.
Непонятное пересечение: сохранить обе версии и решить только конфликт.
```

## Почему

Git хранит часть состояний отдельно; untracked и ignored могут вообще отсутствовать в истории. Ветка не является резервной копией этих данных.

## Когда применять

Всегда при работе в существующем рабочем каталоге. Не читай секретные ignored-файлы ради инвентаризации: достаточно знать, что опасная очистка их затронет. Не меняй состояние index без необходимости задачи.

### Подробные условия

Сравни начальный и итоговый diff, сохраняя чужие изменения. Новая ветка в том же каталоге не изолирует незакоммиченное состояние.

В измененном пользователем файле правь только понятный локальный участок и сверяй актуальное содержимое перед записью. Если разделить изменения нельзя, выдели новый worktree/копию либо согласуй конкретный конфликт. Не применяй reset, clean, массовое восстановление или автоматический stash к неизвестной работе. При параллельной записи повторно прочитай затронутый участок; снимок начала задачи не доказывает, что файл с тех пор не изменился.

## Как проверить

- Есть staged и unstaged правки пользователя → изменить отдельный участок → обе правки и состояние index сохранены.
- Есть untracked/ignored данные → подготовить изоляцию → очистка не выполняется, исходный каталог цел.
- Другой участник изменил тот же участок → применить patch → конфликт обнаружен, чужое содержимое не перезаписано.

## Человек

Уточняет принадлежность действительно неразделимого изменения.

## Агент

Сверяет актуальный diff и в итоговом отчете отделяет свои правки; не использует разрушительную очистку для получения удобной исходной точки.
