# Code review

## Коротко

Ревью проверяет соответствие цели, контракты и риски изменения.

## Плохо

```text
«Код некрасивый, перепиши».
Доступ к чужим объектам не проверен, но один happy path проходит.
```

## Хорошо

```text
blocker, readInvoice: ID берется из запроса без ограничения tenant.
Последствие: пользователь A получает счет пользователя B.
Проверка: запрос A к ID счета B отклонен без раскрытия данных.
suggestion: сократить повторяющееся форматирование.
question: где подтверждена совместимость старого формата?
```

## Почему

Проверка по конкретному риску дает воспроизводимую причину изменения; одна произвольная негативная проверка не покрывает все угрозы.

## Когда применять

Для человеческого и агентного ревью. Глубина зависит от последствия ошибки и зоны diff. Автоматическое замечание требует проверки по коду или воспроизведению, а не принятия по уверенности модели.

### Подробные условия

Для локальной обратимой правки достаточно проверки поведения и diff; для прав доступа, денег, миграции или внешнего эффекта нужны относящиеся к угрозе негативные и граничные сценарии, а при применимости — конкурентность и восстановление.

Замечание содержит место, наблюдаемую проблему, последствие и способ проверить исправление. Отделяй blocker (нарушенный инвариант/обязательная приемка), suggestion (улучшение) и question (нехватка контекста). Непроверенное предположение не называй доказанной ошибкой. Стиль, уже разрешенный проектом, не блокирует изменение из-за личного предпочтения.

## Как проверить

- Рискованный diff → составить относящиеся к нему сценарии → для каждого существенного инварианта есть свидетельство или явный блокер.
- Замечание основано только на стиле → классифицировать → suggestion, если соглашение проекта не нарушено.
- Обнаружено раскрытие чужих данных → оформить blocker → указаны путь, условие, последствие и проверка исправления.

## Человек

Принимает остаточный риск и разрешает содержательные разногласия по контракту.

## Агент

Привязывает замечания к diff и доказательству; отделяет найденный дефект от вопроса и не заявляет полную проверку после частичного чтения.
