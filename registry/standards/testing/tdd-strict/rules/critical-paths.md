# End-to-end тесты

## Коротко

Выбирай сквозные проверки по последствиям отказа: основной пользовательский результат, права, деньги, сохранность данных и существенные интеграции.

## Плохо

```text
Критический тест: страница открылась на узком экране.
Сохранение, чтение другим пользователем и внешний результат не проверены.
```

## Хорошо

```text
AC-6: создать заказ → сохранить → открыть по ID после перезагрузки.
Изоляция: отдельный пользователь и уникальные данные запуска.
Отказ: пользователь B не читает заказ A; ошибка записи не дает успех.
Свидетельство: commit/artifact, среда, ID тестовых объектов и отчет.
Внешний sandbox проверяет интеграцию; mock назван явно.
```

## Почему

Сквозной путь проверяет взаимодействие компонентов, а выбор по риску сохраняет набор приемлемым по стоимости и диагностике.

## Когда применять

Для пользовательских систем с важными путями через несколько границ. Нет обязательства строить E2E для каждой функции или документационной правки. Реальные платежи и сообщения не выполняются ради теста без специальной авторизации.

### Подробные условия

Для каждого пути перечисли границы, которые он обязан пройти, и свяжи его с приемкой. Успешный UI без записи и повторного чтения не подтверждает сохранение.

Изолируй пользователей и данные запусков. Проверяй нормальный путь и относящийся к нему существенный отказ; browser-профиль и узкий экран добавляются, если это риск продукта. Сохраняй версию, среду, входные условия и свидетельство результата. E2E не должен повторять все варианты, которые надежнее и дешевле проверяются на более узкой границе.

## Как проверить

- Критический сценарий → сохранить и заново открыть объект → данные и права подтверждены на указанной версии.
- Второй пользователь → запросить чужой объект → нет доступа ни в UI, ни на серверной границе.
- Два прогона параллельно → выполнить → данные не пересекаются; результат не зависит от порядка.

## Человек

Выбирает критические результаты и допустимые тестовые среды.

## Агент

Проверяет весь перечисленный путь и отдельно сообщает, какие границы заменены mock или не проверены.
