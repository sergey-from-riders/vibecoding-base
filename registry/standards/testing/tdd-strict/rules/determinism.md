# Детерминизм тестов

## Коротко

Тест должен контролировать источники случайности и состояния, которые не являются предметом проверки: время, seed генератора, fixtures и внешние ответы.

## Плохо

```text
Общий пользователь и БД для всех тестов; sleep(5).
Повторять до зеленого, первый сбой удалить из отчета.
```

## Хорошо

```text
Каждый запуск имеет собственные данные; часы/seed контролируются по риску.
Ожидание: нужный status появился до timeout.
Первый прогон failed, retry passed → flaky с сохраненной диагностикой.
Карантин: владелец и срок; критическая приемка обеспечена другим способом.
```

## Почему

Управляемые условия делают сбой воспроизводимым; сохраненная нестабильность позволяет исправить причину вместо маскировки повтором.

## Когда применять

Для автоматизированных проверок. Случайность может быть предметом property/fuzz-теста: тогда сохраняй seed и минимальный воспроизводящий пример, если инструмент их дает. Реальные сетевые задержки не объявляются полностью детерминированными.

### Подробные условия

Тесты не должны зависеть от порядка; параллельные прогоны изолируют БД, файлы, порты и пользователей. Жди наблюдаемое условие с timeout, а не фиксированную паузу как доказательство готовности.

Retry не превращает нестабильность в доказанный успех: сохраняй каждый результат и помечай flaky. Повтор допустим для диагностики либо по явной политике инструмента; исходный сбой не скрывается. Карантин имеет причину, владельца, срок и компенсирующую проверку. Критический сценарий нельзя молча исключить из приемки.

## Как проверить

- Набор в другом порядке и параллельно → выполнить → нет зависимости от чужих fixtures/портов.
- Сбой воспроизводится с определенным seed → повторить → сохранены seed, версия и диагностический пример.
- Первый запуск failed, повтор passed → итог → flaky, а не безусловный passed; карантин не скрывает критический риск.

## Человек

Принимает ограниченный карантин и его компенсирующую проверку.

## Агент

Сохраняет первые ошибки и условия, не повышает retries для сокрытия дефекта.
