# Читаемость кода

## Коротко

У функции должна быть объяснимая задача, у модуля — связанная область. Сохраняйте комментарии о причинах и ограничениях; формальный размер файла не измеряет понятность.

## Плохо

```python
def process(order, send_email, save):
    total = sum(order["prices"])
    save(order, total)
    send_email(order)
    return total
```

## Хорошо

```python
def calculate_total(prices: list[int]) -> int:
    """Сумма неотрицательных цен в одной минимальной единице валюты."""
    if any(price < 0 for price in prices):
        raise ValueError("negative price")
    return sum(prices)
```

## Почему

В хорошем фрагменте выделен только расчет; сохранение и доставка остаются в приложении с собственной транзакционной моделью, не исчезают из продукта. Его легко проверить отдельно. Модуль pricing может содержать несколько связанных расчетов; требование одной функции на файл не следует из одной ответственности.

## Когда применять

Для Python и Go при нетривиальном коде. Применяйте соглашения своего языка: PEP 8 для Python, gofmt/идиомы Go для Go. Ревьюер должен назвать вход, результат, побочные эффекты и причины зависимостей без угадывания. Выделяйте самостоятельный расчет/протокол, если это уменьшает смешение обязанностей; не дробите последовательный простой сценарий на пустые обертки.

Комментарий должен объяснять инвариант, причину обходного решения или внешний контракт и обновляться с кодом. Удаление комментариев ради доли 5%, предел N строк, одна вложенность или число сервисных вызовов не являются универсальными нормами. Локальные пороги линтера служат сигналом ревью с объяснимым исключением. Переименование публичного API оценивается на совместимость.

## Как проверить

1. Новый расчет → ревью другим разработчиком → он определяет вход, единицу, результат и исключение → конкретный разбор и изолированный пример.

2. Правило цены меняется → изменение → не требуется править отправку письма; комментарий обновлен → связный diff и прежние regression-сценарии.

3. Простая последовательная функция превышает локальный порог → ревью → сохранена или разделена с объяснением, без пустых прокси → решение и зависимости после правки.

## Человек

Проверяет предметный смысл и причину разделения, не только форму имен и размер.

## Агент

Показывает, какие обязанности и зависимости изменились; устраняет устаревшие комментарии и проверяет сохранение поведения.
