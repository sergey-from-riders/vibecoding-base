# Читаемость кода

## Коротко

Разделяйте независимые обязанности и сохраняйте объяснения неочевидных решений.

## Плохо

```text
Удалить полезные комментарии, чтобы уложиться в 5%.
```

## Хорошо

```text
Разделить независимые задачи.
Оставить комментарий о причине ограничения.
```

## Почему

Формальный лимит строк не доказывает простоту программы.

## Когда применять

Порог сложности может быть локальным сигналом ревью. Размер файла и доля комментариев не универсальные стандарты.

## Как проверить

- Можно ли назвать одну ответственность модуля и объяснить его зависимости?

## Человек

Проверяет понятность бизнес-смысла и согласует существенные изменения архитектуры.

## Агент

Реализует правило в коде сервиса и проверяет ошибку, отмену и граничные входные данные.
