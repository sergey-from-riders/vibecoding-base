# Источник истины кеша

## Коротко

Для каждого набора кешируемых данных укажите авторитетный источник и воспроизводимый способ восстановления. Единственная копия принятой записи не должна исчезать как обычный кеш.

## Плохо

```text
Заказ подтвержден пользователю, но хранится только в вытесняемом кеше.
После очистки восстановить его невозможно.
```

## Хорошо

```text
Заказ фиксируется в основной БД.
Кеш содержит производное представление с версией источника.
Cache miss → ограниченное чтение источника → проверка → кеш.
Полный снимок публикуется только после проверки целиком.
```

## Почему

Роль определяется гарантиями, не названием продукта: Redis может быть основным хранилищем, но тогда нужны сохранность, копии и восстановление соответствующего уровня. Cache-aside сам по себе не гарантирует согласованность с изменениями основного источника.

## Когда применять

Для производных кешей. Зафиксируйте ключ/версию источника и версию преобразования, если без нее нельзя воспроизвести представление. Для снимка из нескольких файлов/таблиц нужен согласованный commit/snapshot: частичное чтение меняющегося источника не выдается за одну ревизию. Перед переключением текущей версии проверьте полноту и структуру.

Восстановление ограничивает параллелизм, нагрузку БД и время; объединяет одинаковые cache misses или использует контролируемый прогрев. При отказе источника применяется caching.freshness либо явная недоступность. Проверку удаления выполняйте в изолированном тестовом namespace/экземпляре, а не через общий FLUSHALL в production.

## Как проверить

1. Изолированный кеш пуст → запрос/прогрев → данные восстановлены из указанной версии → совпадающий состав/хеш и метаданные.

2. Новый снимок неполный или некорректен → обновление → прежняя исправная версия остается активной → revision и отчет ошибки.

3. Массовый cache miss или отказ источника → восстановление → нагрузка в бюджете, выбранный fallback/ошибка → метрики запросов к источнику и latency.

## Человек

Выбирает источник, предел восстановления и допустимость старых данных.

## Агент

Проверяет воспроизводимость и атомарную публикацию снимка; выполняет очистку только изолированного тестового кеша.
