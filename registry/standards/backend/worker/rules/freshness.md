# TTL и инвалидация

## Коротко

Для каждого кеша задайте возраст свежести, предельный возраст допустимого fallback и событие инвалидации. Ошибка обновления не делает старые данные новыми.

## Плохо

```text
Источник недоступен → продлить TTL старого снимка.
Возраст считается с последнего чтения: устаревание никогда не наступает.
```

## Хорошо

```text
Снимок хранит source_revision и время успешной проверки источника.
До fresh_limit используется по политике.
После — revalidate; при сбое stale разрешен лишь до stale_limit.
Истечение stale_limit → ошибка/запрет опасной операции.
```

## Почему

TTL хранения ключа и бизнес-допустимость устаревания — разные параметры. Удаление ключа не доказывает, что все производные копии исчезли. Значения лимитов и их начало отсчета выбираются для конкретных данных. Данные о правах или финальная цена требуют отдельного решения, а не автоматического применения политики справочника.

## Когда применять

Для прикладного кеша и HTTP-кешей с различными механизмами. Для приложения опишите обновление после commit, revalidation, максимальное отставание и поведение при отказе. Ограничьте одновременные обновления одного ключа; медленный загрузчик старой версии не должен перезаписать более новую. Для снимка сначала проверьте целый кандидат, затем переключите активную версию.

RFC 9111 относится к HTTP: учитывайте Date/Age/Cache-Control и успешную revalidation; он не задает TTL Redis. HTTP-кеш не может выдавать stale вопреки no-cache/must-revalidate или другой запрещающей директиве. Для цен/остатков допустим устаревший показ только при согласованной повторной проверке перед обязательством; для авторизации предел отзыва должен быть явно выдержан.

## Как проверить

1. Источник изменился → commit и refresh/invalidation → новая версия появляется в согласованном бюджете → revision и измерение задержки.

2. Источник недоступен → fresh_limit и затем stale_limit истекли → ограниченный fallback сменяется заданным отказом; часы свежести не сброшены → время источника и ответы.

3. Старый refresh завершился после нового или кандидат поврежден → публикация → активная версия не откатывается/не повреждается → история версий и тест гонки.

## Человек

Определяет допустимое отставание отдельно для справочника, цены, остатка и полномочий.

## Агент

Разделяет время хранения и свежесть, защищает публикацию от гонок и проверяет истечение обоих лимитов.
