# Изоляция кеша

## Коротко

Кеширование персонального ответа не должно обходить текущую авторизацию или смешивать пользователей/tenant. HTTP-директива и ключ прикладного кеша решают разные задачи.

## Плохо

```text
GET /profile пользователя A → общий ключ /profile.
Пользователь B получает тот же кешированный ответ.
```

## Хорошо

```text
Чувствительный HTTP-ответ: Cache-Control: no-store.
Прикладной кеш, если разрешен: tenant + субъект/область + объект + версия прав.
Перед выдачей проверяются текущие полномочия.
При смене аккаунта очищается/переключается клиентское состояние.
```

## Почему

В RFC 9111 private без аргументов запрещает хранение shared-кешем, но допускает private-кеш; no-cache требует успешной проверки перед повторным использованием, а не запрещает хранение. no-store задает запрет HTTP-хранения, но не шифрует данные и не управляет произвольным Redis/localStorage. Одного Vary или tenant_id также недостаточно для авторизации.

## Когда применять

Для данных, различающихся по пользователю, организации или правам. Выберите private с политикой revalidation либо no-store по чувствительности. Не публикуйте персональный ответ как public/s-maxage без доказанного разделения и допустимости shared cache. Проверьте CDN/proxy, browser и прикладные слои вместе.

Идентичность/tenant в ключе берутся из проверенного контекста; если представление зависит от роли/разрешений, версия прав или повторная авторизация должна исключать старый доступ. Определите срок применения отзыва; logout/смена организации сбрасывает клиентские запросы и кеш, чтобы поздний ответ A не попал в состояние B. Сам HTTP-заголовок не стирает ранее сохраненные копии и не защищает от чтения чужого состояния в приложении.

## Как проверить

1. A затем B запрашивают один URL через реальный proxy/CDN → ответы → B не видит A → тела, ключи и cache status.

2. У A отозвано право при прогретом кеше → запрос → отказ в согласованном окне отзыва → журнал решения и отсутствие данных.

3. Logout/смена tenant при незавершенном запросе → поздний ответ → старое состояние не показано новому аккаунту; no-cache без revalidation не переиспользуется → browser-тест.

## Человек

Определяет чувствительность ответа и максимальное окно устаревших полномочий.

## Агент

Проверяет всю цепочку кешей, ключи и смену identity; не заменяет авторизацию HTTP-директивой.
