# Ограничение параллелизма

## Коротко

Ограничивайте одновременно выполняемые и ожидающие задачи до их запуска. Для каждой задачи определите владельца, отмену и способ дождаться завершения.

## Плохо

```text
Для каждого элемента: go func() { взять semaphore; работать }().
Работа ограничена, но ожидающих goroutine может стать миллион.
```

## Хорошо

```text
Профиль примера: N работников и очередь не более Q задач.
Producer ждет место с учетом context либо возвращает перегрузку.
Worker возвращает результат/ошибку и освобождает ресурс.
При shutdown прекращаем прием, отменяем/дренируем и ждем workers.
```

## Почему

Семафор внутри уже созданной goroutine ограничивает активную работу, но не число ожидающих goroutine. Бюджет должен учитывать очередь, память одной задачи, DB pool и лимиты провайдера. N и Q выбираются измерением, не универсальным числом. Data race detector проверяет только реально исполненные пути.

## Когда применять

Для Go при массовой или управляемой пользователем параллельной работе. Выберите поведение полной очереди: ожидание до deadline, явный отказ или допустимое сбрасывание только некритичных задач. Не создавайте goroutine на каждое ожидание места. Контекст должен прерывать блокирующие send/receive и I/O.

У канала один владелец закрытия, обычно producer/координатор после завершения всех отправителей; receiver не закрывает канал, пока в него могут писать. Ошибка worker передается владельцу; политика fail-fast либо независимой обработки задается явно. WaitGroup/Task owner гарантирует ожидание завершения; общий mutable state синхронизирован. Для долговечных заданий память процесса не заменяет устойчивую очередь.

## Как проверить

1. N workers и Q мест → всплеск выше емкости → active ≤ N, queued ≤ Q, остальные ждут/получают отказ по контракту → метрики и ограниченная память.

2. Очередь заполнена → отмена producer/shutdown → blocked send прекращается, workers завершаются в бюджете → счетчики и goroutine profile.

3. Worker вернул ошибку/две задачи меняют общий объект → выполнение с race detector → ошибка доставлена владельцу, нет гонки на покрытом пути или send on closed channel → отчет и результат ожидания.

## Человек

Выбирает N/Q, бюджет shutdown и допустимую реакцию на перегрузку.

## Агент

Ограничивает создание задач до запуска, назначает закрытие каналов и проверяет всплеск, cancel и ошибки workers.
