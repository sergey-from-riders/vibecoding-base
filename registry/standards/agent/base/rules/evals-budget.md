# AI evals

## Коротко

Сравнивай изменение агента с зафиксированным baseline на одном наборе задач и одинаковой конфигурации окружения.

## Плохо

```text
Один удобный запрос ответил красиво — новая версия лучше.
Оценщик: та же модель, тот же ответ, без контрольных случаев.
Лимиты: отсутствуют; неудачные повторы исключены из отчета.
```

## Хорошо

```text
EVAL-3: версия набора, baseline и кандидат зафиксированы.
Задачи: обычные, отказ доступа, конфликт, внешняя prompt injection.
Критерий: доля подтвержденных исходов; критическая утечка блокирует приемку.
Повторы и лимиты выбраны до запуска; расход и все исходы сохранены.
Прерванный бюджетом запуск: incomplete, а не passed.
```

## Почему

Средняя оценка может скрыть редкое нарушение полномочий; контрольные примеры и явный бюджет отделяют улучшение от подгонки и неограниченного эксперимента.

## Когда применять

Для повторно используемого агента или изменения его модели, инструкций и инструментов. Для разовой простой задачи достаточно проверки ее результата. Конкретные пороги и число повторов выбираются по риску, а не копируются из примера.

### Подробные условия

Раздели примеры для разработки и контрольный набор, по которому принимается результат; не подбирай решение только по ответам контрольного набора.

До запуска определи метрики результата, критические нарушения, пороги приемки, число независимых повторов и предел токенов, стоимости и времени. Запиши версии модели, инструкций, инструментов, данных и оценщика; seed фиксируй там, где он поддерживается, без обещания полной воспроизводимости. Оценивай конечное состояние задачи, а не убедительность отчета. Проверь оценщик на известных успешных и ошибочных результатах, а субъективные оценки выборочно сопоставь с человеческим разбором.

## Как проверить

- Baseline и кандидат → одинаковые задачи и условия → отчет содержит все повторы, метрики и расход по версиям.
- Средняя оценка выросла, но есть критическое нарушение → применить заранее выбранный критерий → кандидат не принят; событие сохранено.
- Лимит истек до конца либо оценщик принимает известную ошибку → завершить оценку → incomplete/invalid, без заявления об улучшении.

## Человек

Определяет существенные ошибки и проверяет спорные оценки на контрольных исходах.

## Агент

Не меняет пороги после результата; сохраняет конфигурацию, исходы и расходы, не повторяет испытания сверх разрешенного бюджета.
