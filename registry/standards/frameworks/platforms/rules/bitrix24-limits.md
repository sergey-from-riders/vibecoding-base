# Bitrix24: лимиты и повтор запросов

## Коротко

Ограничивайте поток запросов к порталу и обрабатывайте коды ошибок Bitrix24.

## Плохо

```text
1000 заявок → 1000 одновременных crm.lead.add
Любая ошибка → немедленный повтор
```

## Хорошо

```text
Очередь на портал → ограниченный поток
QUERY_LIMIT_EXCEEDED → задержка с jitter
Неясный результат создания → сверка перед повтором
```

## Почему

Лимит зависит от тарифа и нагрузки. Немедленные повторы усиливают блокировку, а повтор создания может создать дубль.

## Когда применять

Облачный Bitrix24 REST. Учитывайте фактические ошибки, время выполнения и текущие лимиты документации; не фиксируйте одну скорость для всех тарифов. В коробочной версии ограничения настраиваются иначе.

## Человек

Определяет приоритеты синхронизации и допустимую задержку.

## Агент

Добавляет очередь по порталам, ограниченный backoff, метрики и обработку исчерпания повторов.

## Пример применения

Импорт 5000 контактов обрабатывается очередью. После QUERY_LIMIT_EXCEEDED скорость уменьшается; прогресс сохраняется, чтобы перезапуск продолжил импорт.

## Как проверить

- Лимит одного портала не останавливает другой.
- При неизвестном результате записи выполняется сверка.
