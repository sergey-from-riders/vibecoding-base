# Неизменяемый артефакт

## Коротко

Идентифицируй выпуск неизменяемым артефактом: digest или эквивалентным проверяемым ID результата сборки.

## Плохо

```text
Собрать main отдельно для test и production.
Оба результата назвать latest; успешный процесс считать готовым сервисом.
```

## Хорошо

```text
Release R: source C, artifact sha256:D, dependencies L, config revision K.
Проверки выполнены на D; в staging и production продвигается D.
Перед трафиком: readiness; после ограниченного включения: smoke test.
Критерий остановки определен; прежний артефакт доступен.
Публичный выпуск: изменения и способ проверки целостности опубликованы.
```

## Почему

Неизменяемая идентичность связывает проверку с реально запущенным кодом. Проверка происхождения решает другую задачу, чем сравнение digest.

## Когда применять

Для развертываемого ПО и распространяемых артефактов. Если окружение требует отдельной сборки, это отдельный артефакт с собственной проверкой. SSDF/OSPS/SLSA используются по выбранной области и уровню; наличие этой записи не заявляет соответствие им.

### Подробные условия

Свяжи его с commit, разрешенными зависимостями, параметрами сборки и версией deployment-конфигурации без значений секретов. Один commit не гарантирует одинаковый бинарный результат.

Если заявлено продвижение проверенной сборки, в следующую среду переносится тот же артефакт, без повторной сборки под тем же именем. Изменение артефакта требует новой идентификации и относящихся к нему проверок. До переключения трафика проверь readiness; после контролируемого включения — пользовательский smoke test и критерий остановки. Для выпускаемых пользователям компонентов зафиксируй изменения, зависимости и применимые security-решения. Подпись/provenance применяются по модели угроз и выбранному профилю; digest один не подтверждает доверенное происхождение.

## Как проверить

- Проверен D → развернуть → фактический digest совпадает с D; commit и конфигурация доступны без секретов.
- Readiness не прошла → выполнить переключение → новая версия не принимает рабочий трафик, прежняя сохранена.
- Артефакт под тем же тегом изменен → проверить идентичность → несоответствие обнаружено; старый отчет не принят как доказательство.

## Человек

Выбирает критерии выпуска, идентификацию и требования к происхождению.

## Агент

Сверяет фактический артефакт и приемку; не считает build success или liveness достаточной готовностью сервиса.
