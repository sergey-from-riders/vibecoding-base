# Backup и restore

## Коротко

Резервное копирование считается пригодным после восстановления в изолированной среде и проверки нужных данных/сценариев.

## Плохо

```text
Архив БД есть на том же сервере.
Ключ шифрования только на нем; восстановление никогда не запускалось.
```

## Хорошо

```text
Состав: БД + файлы заказов + необходимые роли/конфигурация.
Копии и доступ к ключам проверены вне основного домена отказа.
Учение: восстановить выбранную точку в изолированную среду без рассылок.
Проверки: контрольный заказ, связи файлов, права и повторное чтение.
Отчет: фактические RPO/RTO, начало/конец и отличие от цели.
```

## Почему

Файл копии подтверждает только создание файла; восстановление выявляет отсутствующие ключи, архивы, роли и несогласованные связанные данные.

## Когда применять

Для сохраняемого состояния, потеря которого существенна. Периодичность учений и цели выбираются по ущербу и частоте изменений. Учение не должно отправлять production-платежи/уведомления или перезаписывать рабочую БД.

### Подробные условия

Зафиксируй состав состояния: БД, связанные файлы, конфигурацию, роли, ключи расшифрования и внешние зависимости, которые нужны для запуска. Для каждого компонента определи точку согласованности.

Выбери RPO — допустимую потерю данных по времени — и RTO — допустимое время восстановления, с явными началом и концом измерения. Копия и ключи должны оставаться доступны при потере основного домена отказа; доступ ограничивается и проверяется. Учитывай retention и завершенность цепочки архивов. Для PostgreSQL PITR нужны совместимая base backup и непрерывный нужный WAL; успешное создание одного файла не доказывает восстанавливаемость.

## Как проверить

- Полный комплект → восстановить в изоляции → данные, файлы и права проходят контрольный сценарий.
- Основной сервер недоступен → получить копию и ключи штатным аварийным способом → восстановление остается возможным.
- Отсутствует WAL/ключ либо точка файлов не согласована → провести учение → отказ/потеря явно выявлены, RPO/RTO не объявлены выполненными.

## Человек

Выбирает допустимую потерю и время, назначает владельца копий и аварийного доступа.

## Агент

Проводит разрешенное изолированное восстановление, фиксирует измерения и не выдает наличие архива за успешную проверку.
