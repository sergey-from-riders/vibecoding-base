# vibecoding-base

Открытая база инженерных требований для разработки с ИИ: область применения, нормы, примеры, первоисточники и критерии приемки.

**212 правил, 19 разделов, 26 тематических модулей.** Основной язык — русский. [English overview](README.en.md). Редакция опубликована в справочнике [eval.su/standards](https://eval.su/standards/); точная текущая версия и результаты проверки доступны в [статусе публикации](docs/publication-status.md).

## Редакция от 13 ноября 2026 года

Все **139 оставшихся правил из аудита содержательно переработаны**. Еще три ранее принятых правила — HTTP-статусы, Problem Details и авторизация MCP — сохранены из актуального upstream. Добавлены **70 правил**: 17 языковых, 14 для фреймворков и платформ, 5 по безопасности, 3 по навигации и поиску, 17 по SEO и 14 по персональным данным в РФ.

Исправления внесены в `rules/*.md`: определены условия применения, ограничения, отрицательные и граничные сценарии. Исторические карточки аудита сохранены отдельно. [Реестр изменений](docs/revision-2026-11-13.md) связывает каждый ID с исправлением и проверкой.

Репозиторий содержит Markdown, шесть исходных WebP, лицензию и служебный список исключений Git. CLI, JS/TS-файлы, генераторы, пакетные зависимости, исполняемые тесты и шаблоны приложений отсутствуют. Код внутри Markdown служит примером требования. Реальные проверки выполняются в приложении-потребителе.

## Начать работу

1. Выберите применимые ID в [каталоге](docs/catalog.md). Начальные соглашения языка и фреймворка описаны в [карте требований](docs/language-baselines.md).
2. Используйте профиль [Go + Next.js + PostgreSQL](registry/stacks/go-next-postgres.md), [Python/FastAPI + React + PostgreSQL](registry/stacks/python-react-postgres.md), [публичного сайта РФ](registry/stacks/public-site-ru.md) или [сайта на 1С-Битрикс](registry/stacks/bitrix-site-ru.md).
3. Прочитайте область применения, исключения, примеры и способ проверки каждой выбранной нормы. Уровень «Обязательно» не отменяет ее условия.
4. Зафиксируйте в проекте точный commit корпуса, выбранные ID, критерии приемки, свидетельства и обоснованные исключения. Передавайте агенту релевантное подмножество.
5. Выполните проверки результата. Чтение правила, успешный импорт документа и проверка синтаксиса примера не подтверждают соответствие приложения.

Для сайта подготовлены [матрица приемки](templates/site-acceptance.md) и [матрица операций с персональными данными](templates/ru-data-processing-matrix.md). Они заполняются фактическими URL, сценариями, основаниями обработки и результатами.

## Структура

| Путь | Назначение |
| --- | --- |
| `registry/standards/<domain>/<module>/rules/*.md` | Единственный нормативный текст правила и метаданные |
| `registry/standards/<domain>/<module>/standard.md` | Навигация по модулю и область применения |
| `registry/standards/<domain>/<module>/CHANGELOG.md` | История модуля |
| `registry/handbook/*.md` | Названия, описания и порядок разделов сайта |
| `registry/stacks/*.md` | Профили выбора требований |
| `templates/*.md` | Документационные шаблоны приемки и сопровождения |
| `docs/` | Контракт публикации, редакционные отчеты и история |

Профиль выбирает требования для проекта; модуль объединяет их по технологии или ответственности; раздел организует навигацию сайта. Полные тексты правил не копируются между этими слоями.

## Источники и проверка

[Сопоставление девяти проектов и стандартов](docs/revision-2026-11-13/source-mapping.md) показывает принятые положения Agent OS, agents-md, AGENTS.md, Spec Kit, OpenSpec, BMad, ASVS 5.0.0, SSDF 1.1 и OSPS v2026.08.28. Заимствование отдельных положений не означает полного соответствия этим системам.

[Интеграционное ревью](docs/integration-review-2026-11-13.md) разделяет проверку текста, синтаксический разбор, исполненные изолированные примеры и сценарии, требующие приложения. [Журнал подготовки](docs/validation-standards-revision-2026-11-13.md) сохранен как исторический отчет. Исходные ID, пути, даты первой публикации и schema1 сохранены; 70 новых статей опубликованы 13 ноября 2026 года.

## Публикация на eval.su

Код импорта, валидации, рендеринга, поиска и экспорта сопровождается в проекте eval.su. База предоставляет [контракт контента](docs/content-contract.md). Импортер читает правила, разделы и изображения из одного commit; замена публичной редакции проверяется отдельно.

Историческая приемка перехода на документацию сохранена в [журнале миграции](docs/validation-documentation-only-2026-11-13.md). [Статус публикации](docs/publication-status.md) фиксирует принятие редакции из 212 правил, публичную проверку страниц и скачивания Markdown.
