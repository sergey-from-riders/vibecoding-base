## Server и Client Components

### Коротко

В Next.js загружайте серверные данные на сервере, а интерактивные части выделяйте отдельно.

### Плохо

```text
"use client" во всём дереве страниц, включая чтение секретов.
```

### Хорошо

```text
Server Component загружает данные.
Client Component управляет поиском и кнопками.
```

### Почему

Серверные секреты не должны попадать в браузер; лишний клиентский код увеличивает загрузку.

### Когда применять

Для App Router. В обычном React SPA серверных компонентов может не быть.

### Как проверить

- Нет ли секретов в клиентской сборке? Зачем компоненту use client?

### Человек

Определяет нужную интерактивность и границы доступа к данным.

### Агент

Реализует поведение компонентов и проверяет изменение данных, загрузку и ошибку в браузере.

Контроль результата:

- Нет ли секретов в клиентской сборке? Зачем компоненту use client?

### Пример применения

Страница заказа загружает разрешённые данные на сервере. Кнопка изменения количества — небольшой Client Component; строка подключения к БД не передаётся в props.

## Серверные данные

### Коротко

Общий клиент или серверный модуль должен задавать типы, ошибки и политику кеша.

### Плохо

```text
Каждый компонент по-своему разбирает один ответ API.
```

### Хорошо

```text
Общий клиент: тип результата, ошибка, отмена.
Компоненты получают согласованные данные.
```

### Почему

Расхождение форматов и обработки ошибок делает интерфейс хрупким.

### Когда применять

Это инженерное правило справочника, а не требование протокола. Первоисточник описывает подход или механизм; конкретный процесс выбирается проектом.

Не создавайте второй backend в обработчиках Next без необходимости. Маршрут скачивания документа может быть самостоятельной границей контента.

### Как проверить

- Смена формата API обнаруживается проверкой контракта?

### Человек

Определяет актуальность, доступ и состояния интерфейса.

### Агент

Реализует поведение компонентов и проверяет изменение данных, загрузку и ошибку в браузере.

Контроль результата:

- Смена формата API обнаруживается проверкой контракта?

## Состояния интерфейса

### Коротко

Пользователь должен понимать, идёт ли работа и как продолжить после сбоя.

### Плохо

```text
Любая ошибка сети отображается как «Ничего нет».
```

### Хорошо

```text
Загрузка → список.
Пустой результат → подсказка.
Ошибка → повторить запрос.
```

### Почему

Пустой список и недоступный сервер требуют разных действий.

### Когда применять

Это инженерное правило справочника, а не требование протокола. Первоисточник описывает подход или механизм; конкретный процесс выбирается проектом.

При оптимистическом изменении нужны откат и объяснение ошибки.

### Как проверить

- Проверьте медленную сеть, пустой ответ и отказ доступа.

### Человек

Определяет действия пользователя при загрузке, пустом результате и ошибке.

### Агент

Реализует поведение компонентов и проверяет изменение данных, загрузку и ошибку в браузере.

Контроль результата:

- Проверьте медленную сеть, пустой ответ и отказ доступа.

## Web performance

### Коротко

Оптимизируйте задержку, скачки макета и объём загрузки на целевых устройствах.

### Плохо

```text
Добавить memo везде, не измеряя эффект.
```

### Хорошо

```text
Найти медленный сценарий.
Измерить до и после изменения.
```

### Почему

Локальная оптимизация может усложнить код без заметной пользы.

### Когда применять

Бюджеты зависят от продукта. Web Vitals полезны как ориентир; фиксированный общий лимит JS подходит не каждой странице.

### Как проверить

- Проверьте слабое устройство, загрузку изображений и длинный список.

### Человек

Выбирает реальные страницы, устройства и бюджет производительности.

### Агент

Реализует поведение компонентов и проверяет изменение данных, загрузку и ошибку в браузере.

Контроль результата:

- Проверьте слабое устройство, загрузку изображений и длинный список.
