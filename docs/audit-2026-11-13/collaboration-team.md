## small-pr

**Pull request** · `collaboration.small-pr` · **8/10** · **P2**

[Исходная редакция](https://github.com/sergey-from-riders/vibecoding-base/blob/613500afd8eca5143b4094f6f5cd48e67844f8ff/registry/standards/collaboration/team/rules/small-pr.md) · [Текущий файл](../../registry/standards/collaboration/team/rules/small-pr.md)

Применимость 2/2; Точность 2/2; Границы 1/2; Проверяемость 1/2; Примеры 2/2.

### Что сохранить

Использует связанность задачи, а не произвольный предел строк.

### Что уточнить

1. Не раскрыты зависимые PR и условие самостоятельной проверяемости каждого шага
2. Нет исключения для связного массового переименования или генерации
3. Одна фраза о цели недостаточна для проверки границ diff

### Сценарии приемки

1. Несвязанный рефакторинг вынесен из исправления ошибки
2. Миграция разбита по безопасным этапам, каждый совместим с работающей версией
3. Большое механическое переименование остается одним связным PR с воспроизводимой проверкой

Сценарии предложены для будущей проверки; фактический результат в конкретном проекте не установлен.

### Источники и границы проверки

Прочитан полный текст правила и указанные в нем ссылки. Внешние страницы для этого правила отдельно не перепроверялись; релевантность и актуальность требуют проверки при редактуре.

### Индивидуальный промпт

Используйте вместе с общим промптом и исходным файлом.

```text
Уточни collaboration.small-pr «Pull request», сохранив стабильный ID. Закрой вопросы: Не раскрыты
зависимые PR и условие самостоятельной проверяемости каждого шага; Нет исключения для связного
массового переименования или генерации; Одна фраза о цели недостаточна для проверки границ diff.
Добавь проверяемые сценарии: Несвязанный рефакторинг вынесен из исправления ошибки; Миграция разбита
по безопасным этапам, каждый совместим с работающей версией; Большое механическое переименование
остается одним связным PR с воспроизводимой проверкой. Проверь первоисточники, версии и связанные
статьи. Раздели подтвержденные нормы и новые предложения; задай область и исключения. Верни
Markdown, изменения смысла и открытые вопросы. Не заявляй непроведенные проверки.
```

## ownership

**Распределение изменений** · `collaboration.ownership` · **7/10** · **P1**

[Исходная редакция](https://github.com/sergey-from-riders/vibecoding-base/blob/613500afd8eca5143b4094f6f5cd48e67844f8ff/registry/standards/collaboration/team/rules/ownership.md) · [Текущий файл](../../registry/standards/collaboration/team/rules/ownership.md)

Применимость 2/2; Точность 1/2; Границы 1/2; Проверяемость 1/2; Примеры 2/2.

### Что сохранить

Явно предупреждает, что worktree не устраняет смысловые конфликты.

### Что уточнить

1. Не разделены владелец модуля, автор изменения и ответственный за объединение
2. Нет процедуры согласования изменения общего контракта и порядка интеграции
3. CODEOWNERS сам по себе не обеспечивает сериализацию работы: это нужно сформулировать

### Сценарии приемки

1. Два участника меняют независимые модули с заранее согласованным контрактом и проходят совместную проверку
2. Оба хотят изменить общий DTO: назначается один владелец изменения и новая версия контракта
3. Последовательная малая задача выполняется без искусственного разделения на участников

Сценарии предложены для будущей проверки; фактический результат в конкретном проекте не установлен.

### Источники и границы проверки

Прочитан полный текст правила и указанные в нем ссылки. Внешние страницы для этого правила отдельно не перепроверялись; релевантность и актуальность требуют проверки при редактуре.

```text
согласования изменения общего контракта и порядка интеграции; CODEOWNERS сам по себе не обеспечивает
```

## preserve-changes

**Рабочее дерево Git** · `collaboration.preserve-changes` · **7/10** · **P1**

[Исходная редакция](https://github.com/sergey-from-riders/vibecoding-base/blob/613500afd8eca5143b4094f6f5cd48e67844f8ff/registry/standards/collaboration/team/rules/preserve-changes.md) · [Текущий файл](../../registry/standards/collaboration/team/rules/preserve-changes.md)

Применимость 2/2; Точность 1/2; Границы 1/2; Проверяемость 1/2; Примеры 2/2.

### Что сохранить

Предупреждает о потере чужой работы при массовом сбросе.

### Что уточнить

1. Отдельная ветка не изолирует незакоммиченные изменения; пример может создавать ложное чувство сохранности
2. Не охвачены staged, untracked, ignored и изменения, появившиеся параллельно
3. Нет критерия безопасной частичной правки файла, уже измененного пользователем

### Сценарии приемки

1. В исходном дереве есть чужой staged-фрагмент: после задачи он остается неизменным
2. В том же файле появились новые чужие строки: собственный patch сохраняет их
3. Неизвестный untracked-файл мешает: он не удаляется автоматически и происхождение выясняется

Сценарии предложены для будущей проверки; фактический результат в конкретном проекте не установлен.

### Источники и границы проверки

Прочитан полный текст правила и указанные в нем ссылки. Внешние страницы для этого правила отдельно не перепроверялись; релевантность и актуальность требуют проверки при редактуре.

### Индивидуальный промпт

```text
Отдельная ветка не изолирует незакоммиченные изменения; пример может создавать ложное чувство
сохранности; Не охвачены staged, untracked, ignored и изменения, появившиеся параллельно; Нет
критерия безопасной частичной правки файла, уже измененного пользователем. Добавь проверяемые
```

## review

**Code review** · `collaboration.review` · **7/10** · **P1**

[Исходная редакция](https://github.com/sergey-from-riders/vibecoding-base/blob/613500afd8eca5143b4094f6f5cd48e67844f8ff/registry/standards/collaboration/team/rules/review.md) · [Текущий файл](../../registry/standards/collaboration/team/rules/review.md)

Применимость 2/2; Точность 1/2; Границы 1/2; Проверяемость 1/2; Примеры 2/2.

### Что сохранить

Смещает ревью от стиля к требованиям, правам и совместимости.

### Что уточнить

1. Не задана шкала риска и соответствующий обязательный объем ревью
2. Не различаются блокирующая проблема, рекомендация и вопрос
3. Проверка одного отрицательного сценария не гарантирует покрытие конкретных угроз изменения

### Сценарии приемки

1. Правка оплаты получает проверку повторов и денежных инвариантов по согласованному риску
2. Комментарий ревью содержит путь, наблюдаемую проблему, последствие и способ проверки
3. Мелкая документационная правка не обрастает runtime-тестами без конкретного риска

Сценарии предложены для будущей проверки; фактический результат в конкретном проекте не установлен.

### Источники и границы проверки

## handoff

**Передача результата** · `collaboration.handoff` · **7/10** · **P1**

### Что сохранить

Фиксирует изменения, выполненные проверки и непроверенные ограничения.

### Что уточнить

1. Не указан точный ref или commit результата и состояние незакоммиченных изменений

2. Задача остановлена на внешнем ограничении: указаны сделанное, блокер и следующий шаг
3. Журнал содержит секрет: в передаче остается очищенное свидетельство без значения секрета

## decisions
