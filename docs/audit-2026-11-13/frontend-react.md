## derived-state

**Производное состояние** · `frontend.derived-state` · **9/10** · **P2**

[Исходная редакция](https://github.com/sergey-from-riders/vibecoding-base/blob/613500afd8eca5143b4094f6f5cd48e67844f8ff/registry/standards/frontend/react/rules/derived-state.md) · [Текущий файл](../../registry/standards/frontend/react/rules/derived-state.md)

Применимость 2/2; Точность 2/2; Границы 2/2; Проверяемость 1/2; Примеры 2/2.

### Что сохранить

Четко сформулировано узкое правило и допустимость Effect для внешней системы.

### Что уточнить

1. Нужно обозначить исключение для независимого редактируемого черновика ссылкой на remote-drafts
2. Проверка вопросом может быть заменена наблюдением после изменения исходных данных
3. Пример с ценой требует напоминания, что клиентская сумма не авторитетна для оплаты

### Сценарии приемки

1. Изменение first/last сразу дает согласованный fullName без промежуточной копии state
2. Локальный черновик не удаляется как якобы лишнее состояние, если пользователь редактирует его независимо
3. Тяжелое вычисление оптимизируется только после замера и сохраняет то же значение

Сценарии предложены для будущей проверки; фактический результат в конкретном проекте не установлен.

### Источники и границы проверки

Открыт React You Might Not Need an Effect; пример fullName и различие чистого вычисления/внешней синхронизации прямо поддерживаются источником.

## remote-drafts

**Черновики и серверное состояние** · `frontend.remote-drafts` · **7/10** · **P1**

[Исходная редакция](https://github.com/sergey-from-riders/vibecoding-base/blob/613500afd8eca5143b4094f6f5cd48e67844f8ff/registry/standards/frontend/react/rules/remote-drafts.md) · [Текущий файл](../../registry/standards/frontend/react/rules/remote-drafts.md)

Применимость 2/2; Точность 1/2; Границы 1/2; Проверяемость 1/2; Примеры 2/2.

### Что сохранить

Допускает копию серверных данных ради осмысленного редактирования и вводит revision.

### Что уточнить

1. Не описаны dirty/clean/saving/conflict и момент сброса dirty после успешной записи
2. Не задан серверный compare-and-swap и пользовательский сценарий конфликта revision
3. Нет действий при смене записи, аккаунта, уходе со страницы и фоновом refetch

### Сценарии приемки

1. Фоновый refetch не затирает dirty-поля
2. Сохранение устаревшей revision отклоняется сервером и сохраняет локальный ввод
3. При смене редактируемого ID черновик не переносится на чужую запись

Сценарии предложены для будущей проверки; фактический результат в конкретном проекте не установлен.

### Источники и границы проверки

Прочитан React You Might Not Need an Effect. Он объясняет состояние компонентов, но не является достаточным источником серверного протокола revision: нужна ссылка на concurrency и контракт API.

## url-state

**Состояние в URL** · `frontend.url-state` · **8/10** · **P1**

[Исходная редакция](https://github.com/sergey-from-riders/vibecoding-base/blob/613500afd8eca5143b4094f6f5cd48e67844f8ff/registry/standards/frontend/react/rules/url-state.md) · [Текущий файл](../../registry/standards/frontend/react/rules/url-state.md)

Применимость 2/2; Точность 2/2; Границы 1/2; Проверяемость 1/2; Примеры 2/2.

### Что сохранить

Учитывает shareable state, восстановление и запрет секретов в URL.

### Что уточнить

1. Не определены типы параметров, значения по умолчанию, неизвестные значения и канонизация
2. Нет правила push/replace и ожидаемого поведения Back/Forward при частом вводе
3. Не описаны гонки данных при изменении URL и сброс страницы при смене фильтра

### Сценарии приемки

1. Новая вкладка воспроизводит те же фильтры и сортировку
2. Back/Forward восстанавливает состояние и данные без отдельного расходящегося store
3. Некорректный query нормализуется безопасно, а секреты и чувствительный текст не записываются в адрес

Сценарии предложены для будущей проверки; фактический результат в конкретном проекте не установлен.

### Источники и границы проверки

Прочитан полный текст правила и указанные в нем ссылки. Внешние страницы для этого правила отдельно не перепроверялись; релевантность и актуальность требуют проверки при редактуре.
