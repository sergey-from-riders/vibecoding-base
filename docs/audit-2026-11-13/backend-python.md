## async

**Async I/O** · `backend.async` · **8/10** · **P1**

[Исходная редакция](https://github.com/sergey-from-riders/vibecoding-base/blob/613500afd8eca5143b4094f6f5cd48e67844f8ff/registry/standards/backend/python/rules/async.md) · [Текущий файл](../../registry/standards/backend/python/rules/async.md)

Применимость 2/2; Точность 2/2; Границы 1/2; Проверяемость 1/2; Примеры 2/2.

### Что сохранить

Правильно отделяет I/O от CPU и оговаривает обычную GIL-сборку.

### Что уточнить

1. Не описаны отмена задачи, корректная очистка ресурсов и утечки фоновых задач
2. Нет границ параллелизма при массовом создании tasks
3. Тест отзывчивости без бюджета и нагрузки остается субъективным

### Сценарии приемки

1. Медленный I/O не блокирует независимый легкий запрос сверх бюджета
2. Отмена закрывает клиент/ресурс и не оставляет незавершенные бесхозные задачи
3. Большое число работ ограничено concurrency-бюджетом, а CPU-задача вынесена по выбранному профилю

Сценарии предложены для будущей проверки; фактический результат в конкретном проекте не установлен.

## typed-boundaries

**Валидация типов** · `backend.typed-boundaries` · **6/10** · **P1**

[Исходная редакция](https://github.com/sergey-from-riders/vibecoding-base/blob/613500afd8eca5143b4094f6f5cd48e67844f8ff/registry/standards/backend/python/rules/typed-boundaries.md) · [Текущий файл](../../registry/standards/backend/python/rules/typed-boundaries.md)

Применимость 2/2; Точность 1/2; Границы 1/2; Проверяемость 1/2; Примеры 1/2.

### Что сохранить

Различает статическую типизацию и runtime-валидацию.

### Что уточнить

1. Нет конкретного Pydantic DTO со strict/coercion, диапазоном и extra-политикой
2. Не различены отсутствующее поле, null, bool и целое число в JSON
3. Не показан согласованный формат ошибок и отдельная авторизация

### Сценарии приемки

1. Допустимое целое quantity проходит и используется после валидации
2. Отрицательное, превышающее предел, bool и строка обрабатываются по явной политике
3. Неверный ввод не вызывает charge и не раскрывает чувствительные внутренние данные

Сценарии предложены для будущей проверки; фактический результат в конкретном проекте не установлен.

## readable-code

2. Разбиение сохраняет поведение и уменьшает смешение обязанностей
3. Полезный комментарий причины остается даже при превышении произвольной доли комментариев
